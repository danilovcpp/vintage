# UX/UI design standard

1. Discover tasks, not aesthetics first: user jobs, frequency, environments, alternatives, information architecture, navigational depth.
2. Deliver site map, actor journeys, stateful user flows, forms/data tables/search/filter/sort/access control, destructive-action confirmation where relevant.
3. Wireframes before high fidelity. Explain each view's hierarchy, primary action, density, progressive disclosure, critical feedback and validation. Use concrete copy, avoid lorem ipsum for core flows.
4. Design system: typography scale, spacing, radii, breakpoints, color role tokens (light/dark when required), semantic status, component states, form primitives, icons, contrast, focus and motion. Reuse existing kit if available, avoid needless bespoke components.
5. Every key screen: loading, skeleton if useful, empty, no results, partial loading, permission denied, offline (if relevant), errors, success, destructive confirmation, keyboard/screen-reader, narrow viewport.
6. Accessibility by design: WCAG 2.2 AA as a target where applicable; test contrast, accessible names/semantics, focus order, reduced motion, target size. Standard target must be verified against project constraints.
7. Visual deliverables: description + low-fi diagrams, high-fi in a supported editable tool where available, screenshot/prototype evidence. Never present textual descriptions as if rendered Figma files exist.
8. Review with target user's tasks, time-to-complete, error prevention, learnability, and consistency. Document rejected variants and rationale.
