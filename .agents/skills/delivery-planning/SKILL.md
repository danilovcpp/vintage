# Delivery plan

Read approved PRD, SRS, architecture and UX or note missing approvals. Use `templates/07_DELIVERY_PLAN.md`. Organize foundational technical risk spikes, thin end-to-end MVP, then incremental vertical slices. Each phase includes outcome, explicit scope, dependencies, impacted disciplines, effort range with assumptions, acceptance tests, observability and demo evidence, rollout/rollback when applicable.

Include CI/CD, security/privacy, migration, design, QA, docs and operational readiness work rather than treating them as footnotes. Identify critical path, reserve, fallback cuts and milestone-go/no-go gates. Tag tasks with REQ/ADR IDs. Ask owner to approve *one phase* before code work; estimates are scenario-dependent, not commitments.
